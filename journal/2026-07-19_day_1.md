## Meow — raw questions worked through

- Most common tool for finding open ports: nmap
- Port 23/tcp service identified: Telnet — plaintext, no encryption at
  all, mostly replaced by SSH (port 22) which does the same job encrypted
- `nmap -sV <target-ip>` scans common ports + identifies service/version

Port reference table built while working through this:
21 FTP, 22 SSH, 23 Telnet, 25 SMTP, 53 DNS, 80 HTTP, 443 HTTPS, 445 SMB,
3306 MySQL, 3389 RDP

Random notes: packet sniffing = capturing/reading raw traffic (Wireshark).
Ping = basic reachability check. flag.txt/user.txt/root.txt = the file
you need to "own" the machine.

## Fawn — raw questions worked through

- FTP usually listens on port 21
- Secure successor to FTP, extension of SSH: SFTP (Secure File Transfer
  Protocol) — encrypts both login credentials and data

## Nmap scan walkthrough — own PC, for practice

Difference between normal scan and `-sV`: normal scan just shows which
common ports answer; `-sV` also identifies the actual software/version
behind each one, because security depends on the exact version running.

Steps run:
1. `nmap --version` — confirmed it works
2. `ipconfig` → found local IPv4 under "Wireless LAN adapter Wi-Fi"
3. `nmap 192.168.1.25` — basic scan, ~76s, showed port type + service
4. `nmap -sV 192.168.1.25` — version scan. Notes from output:
   - "Host is up" = target responded
   - "996 filtered tcp ports" = default 1000 checked, 996 no response, 4 open
   - `2x1/tcp` shown as `?` — Nmap guessing FTP, not confirmed
   - Port 554 = RTSP (Real Time Streaming Protocol)
   - Port 1723 = PPTP (Point-to-Point Tunneling Protocol, VPN)
   - Port 5060 = SIP (Session Initiation Protocol, VoIP)
5. `nmap -A 192.168.1.25` — aggressive scan: OS detection + version +
   script scanning + traceroute in one pass
6. `nmap -p- 192.168.1.25` — full port sweep, all 65535, ~193s

### Mistake made

Scanned the wrong device — my gateway (192.168.43.1) instead of my own
PC (192.168.43.4), because I didn't check `ipconfig` carefully enough
before scanning. Lesson locked in: find target IP → confirm it belongs
to the intended device → THEN scan. Skipped step 2, wasted a scan cycle.
